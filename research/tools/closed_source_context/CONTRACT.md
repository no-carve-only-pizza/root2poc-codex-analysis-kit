# Closed-source context runtime contract

> Status: IMPLEMENTED PAPER-ADAPTED V2 — automated tests and live manual and forced automatic compaction acceptance passed on 2026-08-27; vulnerability-analysis lift remains a separate experiment.

This subsystem preserves bounded analysis state around Codex compaction. It adapts Slyp's recent-tool preservation, external checkpoint, structured summary, post-compaction recovery, and tentative-claim revalidation to project-local Codex hooks. It does not reproduce Slyp's agent scaffold, compaction-model call, per-turn memory index, crash-based completion condition, or general stop-time verifier.

The runtime does not choose targets, order discovery, measure coverage, prove a claim, or replace canonical evidence. The active discovery prompt owns the current completion floor. When that floor is `RCE_REQUIRED`, a crash, denial of service, null dereference, or read/write/UAF primitive is intermediate progress.

References: [Slyp paper](https://arxiv.org/html/2605.05000v2), [OpenAI Codex hooks](https://learn.chatgpt.com/docs/hooks).

## Capture boundary

- `UserPromptSubmit` stores a redacted, bounded objective plus a pointer to its redacted hook-visible capture. A continuation prompt generated by this runtime's Stop guard is labeled separately and cannot replace the latest real user objective in the capsule.
- `PostToolUse` accepts `mcp__idalib__*` results and Bash results only when the command invokes CDB, WinDbg, NTSD, debugger heap/verifier setup, or a debugger script. Generic Bash is ignored.
- `Stop` stores the redacted latest assistant message before the completion guard evaluates it.
- CDB Bash hooks normally receive model-facing output. IDA MCP hooks receive the MCP result exposed by Codex. Either may already be truncated before this runtime sees it.
- Stored tool captures are labeled `hook_visible_only`. `checkpoint.jsonl` contains bounded summaries and capture pointers; `raw/` retains the redacted hook-visible value up to the local capture cap. Neither is a complete debugger transcript.
- Hosted tools, hidden reasoning, and the unstable Codex transcript format are not read or claimed as captured.

Raw CDB logs, dumps, PoCs, controls, exact commands, binary and input hashes, OBS files, and same-day `llm-log.md` entries remain canonical evidence. Promote claim-relevant native artifacts into the target's `evidence/` directory before cleanup.

## Analysis activation

Recovery activates automatically only after the session stores at least one tool event explicitly classified as `ida` or `cdb` by the allowlisted adapter. A planning, translation, or documentation session with no such result receives no closed-source recovery capsule after compaction. The user does not need to toggle a mode.

## Lifecycle behavior

### Before compaction

`PreCompact` records a lifecycle marker. For an active analysis session it then:

1. preserves the two latest captured IDA/CDB request-response pairs in `recent-tools.jsonl`;
2. retains the full redacted hook-visible event trajectory in append-only `checkpoint.jsonl` and records its path and SHA-256;
3. writes capsule schema v2 from the complete captured trajectory rather than only the latest message.

The deterministic reducer preserves the latest real user objective, exact-target hints, current hypothesis, work state, methodology notes, cross-function relationships, runtime state, latest explicit claim boundaries, confirmed/refuted/tentative statements, the next discriminating test, canonical evidence pointers, and separate derived-capture pointers. Canonical pointers are normalized inside the project and traversal or `.agent-state` paths are rejected. When the exact same normalized claim receives multiple explicit statuses, the latest status wins. Semantically equivalent rewordings still require model or human revalidation.

The capsule always labels itself as derived state. It records `RCE_CLAIM_REQUIRES_CANONICAL_REVERIFICATION` when it sees an explicit positive RCE statement; it never records `RCE_PROVEN`.

### After compaction

`PostCompact` records an audit marker. `SessionStart` with `source=compact` injects recovery context only for an active analysis session. The injected context includes the completion floor, objective, exact target, methodology, active claims, checkpoint pointer, canonical evidence pointers, derived-capture pointers, the next test, and at most two recent tool pairs. In the accepted Codex 0.147.0 run, compact-source `SessionStart` was delivered lazily on the first submitted post-compaction prompt, before the model answered, rather than at the instant `/compact` finished.

Recovery output is capped at 4,800 characters and 6,000 UTF-8 bytes. Those runtime caps are the actual model-context budget. The handler's larger `additionalContextLimit` is only a transport spill ceiling so the already-bounded recovery text reaches the model intact; it does not authorize more injected content. Optional lines are dropped before any critical completion or revalidation directive. The full checkpoint is never injected automatically.

### Turn stop

The completion guard is intentionally narrow. It runs only when all of the following are true:

- the session has captured an allowlisted IDA/CDB result;
- the active discovery prompt explicitly declares `RCE is the minimum success condition`;
- the last assistant message explicitly declares the overall discovery or analysis complete;
- that message does not contain an explicit, non-negated positive RCE statement;
- the user did not explicitly stop; and
- `stop_hook_active` is false, so the guard cannot loop.

When these conditions hold, the hook asks Codex to continue once and reminds it that crash-only or primitive-only evidence is incomplete. It does not block bounded experiment completion, user-requested stops, permission boundaries, or targets whose active prompt defines another completion floor.

Explicit overall non-completion statements, including morphologically negated output in supported languages, are not completion claims. An explicit positive status line such as `Status: COMPLETE` still takes precedence over a contradictory disclaimer elsewhere in the same answer.

## Generated local state

```text
research/.agent-state/closed-source/
├─ runs/<safe-session-id>/
│  ├─ raw/
│  ├─ checkpoint.jsonl
│  ├─ capsule.yaml
│  └─ recent-tools.jsonl
└─ index/bm25-cache/finding-cards.json
```

The runtime sanitizes session identifiers, contains storage and extracted canonical-evidence pointers inside the project, redacts recognized credentials before persistence, caps captures, records truncation and hashes, uses atomic replacement, locks checkpoint and capture access, and deduplicates event IDs. `.gitignore` excludes generated state. Redaction is defense in depth, not permission to store secrets.

## Finding memory and retrieval

`retriever.py` indexes only `*/findings/FIND-*.md`. It requires `--reason primitive-promotion` or `--reason chain-review`, returns at most three BM25 matches, and never runs from a per-turn hook.

```text
python3 research/tools/closed_source_context/retriever.py \
  --reason primitive-promotion search "native primitive and exact consumer" --top 3
```

A match is a hypothesis hint, never exploit-chain evidence. Finding cards must already satisfy the promotion gate in `templates/finding-card.md`. This deliberately does not copy Slyp's per-turn compact index and topic-file injection.

## Tool-output boundary

Slyp applies progressive truncation inside its own agent scaffold. Current Codex `PostToolUse` hooks cannot rewrite a completed MCP result, so this runtime does not pretend to provide equivalent active-context truncation. Oversized hook-visible captures retain bounded head/tail data, the redacted full-input hash, and a truncation flag. If live IDA/CDB output still causes pre-compaction overflow, implement reduction at the IDA/CDB adapter boundary and evaluate it separately.

## Activation and acceptance

Start Codex at the project root, open `/hooks`, review `.codex/hooks.json`, and trust the project hook. Project hooks merge with existing user hooks and a current session cannot retroactively load a newly changed hook.

Automated tests cover JSON shape, allowlisting, inactive-session suppression, two-pair retention, trajectory status resolution, methodology reinjection, RCE negation, one-shot completion continuation, explicit user stop, secret redaction, path containment, idempotency, concurrent append, bounded reinjection, deterministic A/B/C/D recovery fidelity, finding-card retrieval, and target-independent project boundaries.

Live acceptance exercised inactive-session suppression, allowlisted IDA capture, two manual compaction cycles, forced automatic compaction, bounded model-visible recovery, preservation of the latest real user objective, and the one-shot completion guard. Target identifiers and native evidence are intentionally excluded from this shared repository.

`evaluation.py` runs a no-model, fixed-trajectory A/B/C/D recovery-fidelity smoke test. A and B retain 0/15 dynamic markers, the latest-message C baseline retains 8/15, and paper-adapted D retains 15/15 in 1,996 UTF-8 bytes. This validates arm construction and exact state retention, not model behavior or vulnerability-discovery lift. The proposed same-model, same-target, same-tool, same-wall-clock vulnerability-analysis comparison remains a separate empirical experiment. A separate compaction-model call, if ever added, must be measured as another arm with its token, latency, and cost overhead disclosed.
